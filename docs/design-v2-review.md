# AlleSchools V2 设计大扫除 Review

状态：开发前阻断 review  
审查对象：`docs/design-v2.md` v1.0  
日期：2026-08-30  
方法：同类职责合并、删除反事实、SoT/Projection 与维护机制检查

## 1. 结论

`docs/design-v2.md` 的产品方向成立，但当前还不能作为稳定的开发 SoT。

主要风险不是视觉细节，而是若干核心状态没有唯一语义：VO overview、学校搜索与市镇筛选、比较状态分享、最低样本量以及验收证据。继续实现会产生多个行为都“符合文档”、但彼此不兼容的结果。

开发前必须关闭第 2 节的五个阻断项。第 3 节可以跟随相邻实现切片关闭。阻断项关闭前，页面骨架和无争议视觉工作可以继续；状态模型、URL、profile 和比较功能不得宣称完成。

## 2. 阻断项

### R01 — VO `overview` 没有数据语义

- 严重性：P1
- 证据：设计要求 VO 默认显示 overview，并让 NT、NG、EM、CM 在同一画布切换；没有定义 overview 的 points、Y 轴、聚合公式或缺失数据回退。
- 删除反事实：删除 overview，仅保留四个已有 profile，不会损失任何已经定义的数据行为。
- 风险：不同实现者可能选择四图叠加、均值、第一 profile 或旧 VO 指标，都会生成不同产品。
- 决策要求：
  - 方案 A：删除 overview，VO 默认 NT；或
  - 方案 B：在 `docs/schema.md` 增加 overview 的正式数据与指标契约。
- 关闭证据：设计正文、schema、URL 枚举和测试对同一方案一致。

### R02 — 学校搜索与市镇筛选职责重叠

- 严重性：P1
- 证据：核心任务规定搜索支持市镇，组件设计又提供独立地区筛选。
- 删除反事实：从主搜索删除市镇匹配不会降低用户能力，因为地区筛选已经提供等价且更明确的行为。
- 风险：无法确定 Amsterdam 应当高亮、过滤，还是与独立地区字段做交集。
- 建议决策：
  - 主搜索 canonical 职责：校名、缩写、BRIN、邮编；
  - 地区筛选 canonical 职责：市镇；
  - 两者组合采用交集。
- 关闭证据：设计、placeholder、纯逻辑测试和 URL 回放使用相同规则。

### R03 — 比较状态的分享契约自相矛盾

- 严重性：P1
- 证据：设计原则声明“选择状态具有明确 URL 语义”，分享字段和 F07 却没有 comparison。
- 风险：复制链接、社交分享和页面刷新可能丢失用户正在比较的学校。
- 决策要求：
  - 方案 A：`compare=<stable-id csv>` 进入 URL，并由 F07 验收；或
  - 方案 B：明确比较列表是 session-only，从设计原则移除分享承诺。
- 建议：采用方案 A。最多四个稳定 ID，URL 长度可控。
- 关闭证据：同一个 serializer 被复制链接、X、Facebook 和页面回放共同使用。

### R04 — 最低样本量筛选跨越数据准入边界

- 严重性：P1
- 证据：设计增加“最低样本量”筛选；流水线已经在发布前按阈值排除学校。
- 删除反事实：删除该筛选不会损失已发布数据的核心探索能力。
- 风险：用户可能误以为浏览器筛选能恢复已在 pipeline 中排除的数据，或把展示过滤误认为数据质量规则。
- 建议决策：删除该筛选。若确有需求，命名为“仅显示样本量至少 N 的已发布学校”，且 N 不得低于发布阈值。
- 关闭证据：设计中不再出现无数据来源的筛选入口。

### R05 — Goal 完成条件依赖无维护机制的人工验收

- 严重性：P1
- 证据：Goal 要求第 10 节全部满足；现有命令只验证 Python、Node、依赖与静态构建，无法证明 F01–F10、键盘操作、四种 viewport、三种语言和浅深主题。
- 删除反事实：删除不可执行的笼统完成声明，不会降低真实质量；只会避免虚假完成。
- 风险：同一 revision 可以在没有浏览器证据的情况下被标记完成。
- 决策要求：每个验收项标记为：
  - `automated`：给出测试文件或命令；
  - `manual`：给出 viewport、操作步骤、预期结果和 receipt 路径。
- 建议 receipt：`artifacts/acceptance/<commit>/acceptance.json`，记录 exact commit、浏览器、viewport、语言、主题、结果和截图路径。
- 关闭证据：Goal 的每个终态条件都有可回读的 exact-commit receipt。

## 3. 高优先级收敛项

### R06 — 实时搜索和执行按钮重复

- 严重性：P2
- 证据：设计同时要求输入即时高亮，以及 Enter/按钮触发相同行为。
- 删除反事实：实时搜索存在时，执行按钮不增加结果能力。
- 建议：采用实时搜索，删除执行按钮；移动端可保留“完成”作为关闭键盘的呈现动作，但不能成为第二套搜索机制。

### R07 — URL 契约没有固定

- 严重性：P2
- 证据：设计描述了 URL 状态语义，但没有固定参数名、默认省略、排序、非法值处理和旧链接兼容。
- 当前漂移风险：已有实现出现 `q`、`search`、`gemeente`、`city`、`profile`、`compare` 等候选键。
- 建议 canonical 契约：

```text
lang=en|zh|nl
mode=vo|po
q=<search text>
gemeente=<csv>
profile=nt|ng|em|cm
compare=<stable-id csv>
```

- 状态优先级：URL > localStorage > default。
- 兼容策略：读取旧键，写出时只使用 canonical 键。
- 关闭证据：规范化、序列化、反序列化和旧链接迁移测试。

### R08 — 比较指标缺少生命周期与身份规则

- 严重性：P2
- 未定义项：
  - VO profile 切换后比较值是否同步；
  - VO/PO 切换是否清空不兼容选择；
  - 相同 BRIN 在不同 profile 中是否是同一学校；
  - 缺失 X/Y 时是否允许加入比较；
  - 稳定 ID 使用 BRIN、vestiging，还是 layer + BRIN。
- 建议：稳定身份使用 `layer + school-id`；profile 是视图状态，不进入学校身份。切换 layer 时清空不兼容比较项，切换 profile 时保留学校并刷新当前 profile 指标。

### R09 — 颜色存在多个竞争职责

- 严重性：P2
- 证据：视觉规范定义四个固定系列色；现有图表使用颜色表达市镇，未来还需要表达匹配、选中和比较。
- 风险：同一颜色通道同时承担市镇、profile 和选择状态，用户无法解码。
- 建议 canonical 编码：
  - 基础点：统一中性色；
  - 搜索命中：陶土橙；
  - 比较选中：森林绿边框和编号；
  - 市镇不再使用唯一颜色图例；
  - profile 由标签和轴标题表达，不用点色表达。

### R10 — “不制造排名”没有内容验收

- 严重性：P2
- 证据：这是设计原则，但验收矩阵没有禁止排名暗示。
- 建议新增内容门禁：用户可见文案不得出现无正式契约支持的 `best`、`elite`、`strength`、`最佳`、`精英`、`更强` 等判断性表达。
- 关闭证据：静态文本扫描加三语言人工 review。

## 4. 可删除或压缩项

### R11 — Persona 列表没有驱动差异化行为

- 严重性：P3
- 证据：三类用户没有对应不同权限、路径、默认值或组件。
- 删除反事实：删除三类 persona，不改变任何设计或验收行为。
- 建议：压缩为一个主用户陈述：“正在形成或比较学校候选名单的家长与学生”；研究型使用保留为“查看方法论”任务。

### R12 — 顶部导航与页面内容可能形成重复入口

- 严重性：P3
- 判断：Methodologie、Over de data、Contact 具有明确触发时机，可以保留为同页锚点；不应再创建独立页面或复制正文。
- canonical home：正文区块是内容 SoT，顶部导航只是定位入口。
